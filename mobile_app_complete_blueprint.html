Phase 1 — Onboarding & Authentication
First thing the app does. Every role goes through this. Build this before anything else — everything depends on it.
Sprints 1–3 · Weeks 1–6
App install & version control
Dual distribution channels
App available on Google Play Store and Apple App Store publicly. Also as a private APK/IPA link hosted on company server for corporate-managed devices. On first launch, app checks current version against server — if outdated, a mandatory update screen blocks all access until updated.
TraineeTrainerSupervisor
Stack: React Native FastAPI version-check endpoint Google Play / App Store / internal CDN for APK
Employee ID + mobile number login
User enters Employee ID and registered mobile number on login screen. FastAPI cross-references both fields against the HR Master Data table in MySQL. If no match found, login is blocked with a "Contact your admin" message. No password needed at this stage.
TraineeTrainerSupervisor
Stack: React Native form FastAPI /auth/verify-identity MySQL users table
SMS OTP activation
After identity verified, a 6-digit OTP is sent to the registered mobile number via SMS gateway. OTP expires in 5 minutes, max 3 attempts. On success, account is activated and a JWT access token + refresh token is issued. Also used for password recovery and supervisor proxy login.
TraineeTrainerSupervisor
Stack: MSG91 or Twilio SMS gateway FastAPI /auth/send-otp + /auth/verify-otp Redis for OTP storage with TTL
Device binding
On first successful login, the device's unique identifier (Android ID or iOS identifierForVendor) is stored against the user's account. Future logins from a different device are blocked unless admin resets the binding. This prevents proxy attendance by using a friend's phone. Supervisor devices are exempt — they use shared device mode.
TraineeTrainer
Stack: react-native-device-info (getUniqueId) FastAPI stores device_id on users table MySQL users.device_id column
Live photo capture & face match
After OTP success, app opens front camera. Trainee snaps a selfie. The photo is sent to the AI face service which compares it against the HR profile photo stored in the database. A liveness check detects if someone is holding a printed photo in front of the camera. Confidence score below threshold = registration blocked, alert sent to admin.
Trainee
Stack: react-native-camera or expo-camera AWS Rekognition (CompareFaces + DetectFaces liveness) FastAPI /auth/verify-photo S3 for photo storage
JWT session + role-based routing
On successful login, JWT contains the user's role (TRAINEE / TRAINER / SUPERVISOR). The app reads this token and routes to the correct home screen — each role sees a completely different dashboard. Refresh token stored securely in encrypted device storage. Session auto-expires after inactivity timeout.
TraineeTrainerSupervisor
Stack: react-navigation (role-based stack) python-jose for JWT react-native-keychain (secure token storage)
Language selection
First-time users see a language picker after login. Options: English, Hindi, Marathi, Tamil, Telugu, Kannada, Bengali, Odia. Selection persists locally. All screens, labels, and assessment questions then load in chosen language. User can change language anytime from profile settings.
TraineeTrainerSupervisor
Stack: i18next + react-i18next AsyncStorage for language preference Unicode-compliant fonts (Noto Sans family)
Phase 2 — Notifications, Invites & Pre-study
What happens before a trainee walks into training. Invites, material access, and baseline testing.
Sprints 4–5 · Weeks 7–10
Training invites & notifications
Push notification — training invite
When admin publishes a session on web, the system auto-sends push notifications to all enrolled trainees. Notification shows session name, date, time, location. Trainee taps it to open the session detail screen in the app. RSVP buttons (Accept / Decline) inside the screen.
Trainee receives
Stack: Firebase FCM (push notifications) @react-native-firebase/messaging FastAPI background job triggers FCM on session publish
Reminder alerts — 24h and 1h before
Scheduled background jobs fire push notifications 24 hours before the session starts and again 1 hour before. Trainee sees: "Your Fire Safety training starts in 1 hour at Block B Campus." These are separate from the invite notification.
Trainee receives
Stack: Celery + Redis as task queue Firebase FCM FastAPI scheduled tasks (APScheduler or Celery beat)
QR code enrollment check-in
Invite includes a unique QR code per trainee per session. At the venue entrance, trainee scans it using the in-app QR scanner. System instantly validates and marks them as arrived. Trainer sees real-time arrival count on their trainer dashboard screen.
Trainee scansTrainer sees count
Stack: react-native-camera / expo-barcode-scanner FastAPI /sessions/checkin-qr qrcode (Python) for QR generation
Pre-study materials
Study materials unlock (48–72h before)
48–72 hours before the session, materials assigned to that session automatically become visible in the trainee's app under "Upcoming Sessions." PDFs, PPTs, and videos appear in a locked in-app viewer — no download button, no share option. Trainee can read/watch inside the app only.
Trainee reads
Stack: AWS S3 pre-signed URLs (time-limited) react-native-pdf for PDF viewing react-native-video for video playback FastAPI /materials/unlock (scheduled job)
Offline download of materials
Trainee can download materials to device while on Wi-Fi for offline access at remote sites. "High Quality" or "Data Saver" version choice shown before download. Files stored in encrypted local SQLite/filesystem. Download progress bar shown per file.
Trainee downloads
Stack: react-native-fs (filesystem access) react-native-sqlite-storage (local DB) react-native-aes-crypto (encryption at rest)
Pre-assessment (baseline test)
Baseline test before training
Before attending the session, trainee takes a short MCQ/True-False test. Questions pulled randomly from question bank for this topic. Timer shown on screen. Results saved as pre-score — not used for pass/fail, only to measure how much the trainee improved post-training.
Trainee takes
Stack: FastAPI /assessments/pre-test MySQL question_bank, assessment_attempts tables React Native timer + MCQ UI components
Phase 3 — Attendance & Session Start
Verifying the trainee is physically present at the right location at the right time.
Sprints 6–7 · Weeks 11–14
Geo-fenced attendance
GPS location check on check-in
When trainee taps "Mark Attendance," app reads current GPS coordinates and sends them to the API. Server checks if coordinates fall inside the campus geo-fence polygon stored in the Campus master. If outside, check-in is rejected with "You are not at the training venue" message. Admin can override remotely if needed.
Trainee marks
Stack: react-native-geolocation-service FastAPI /attendance/checkin (polygon check via Shapely) Shapely (Python) for point-in-polygon geo math MySQL campus_geofence table (lat/lng polygon)
Biometric authentication for check-in
After geo-fence passes, trainee confirms identity via device fingerprint or Face ID. This uses the phone's native biometric system — no biometric data leaves the device. A success callback is sent to the app, which then finalizes the check-in API call with a biometric_verified: true flag.
Trainee authenticates
Stack: react-native-biometrics Android BiometricPrompt / iOS LocalAuthentication FastAPI /attendance/finalize
Trainer session start actions
Trainer views live attendance dashboard
Trainer's home screen for an active session shows real-time list of who has checked in, who is pending, and who is absent. Updates automatically as trainees check in. Trainer can manually mark someone absent or force-mark present if biometric fails and they are physically verified.
Trainer views and acts
Stack: React Native FlatList with polling or WebSocket FastAPI /sessions/{id}/attendance-status Redis for real-time attendance state
Batch group photo upload by trainer
At session start, trainer is prompted to photograph the full group assembled in the room. Photo is uploaded to S3 and the AI face service counts faces and matches each against the check-in list. If headcount doesn't match digital check-ins, an alert is flagged for admin review before results are published.
Trainer photographs
Stack: react-native-camera AWS Rekognition (DetectFaces for headcount) AWS S3 for photo storage FastAPI /sessions/group-photo
Phase 4 — In-session Learning
What trainees, trainers, and supervisors do during the actual training session.
Sprints 8–10 · Weeks 15–20
Trainer content delivery
Timed release — unlock content mid-lecture
Trainer sees a list of materials assigned to the session, each with a lock icon. Trainer taps "Unlock Now" next to a specific file during the lecture. The API instantly makes that file visible to all enrolled trainees' apps. Prevents trainees from reading ahead before the trainer covers that topic.
Trainer unlocksTrainee receives
Stack: FastAPI /materials/release (sets released_at timestamp) React Native real-time update via polling / WebSocket MySQL session_materials.is_released column
Trainee content consumption
Secure in-app document viewer (PDF/PPT/video)
Trainee opens released materials inside a sandboxed viewer. No download button, no share sheet, no screenshot prevention (best-effort). PDFs rendered natively. Videos stream from S3 pre-signed URL with progress tracking — video must reach 100% before marked complete. Seeking to end is detected and blocked.
Trainee views
Stack: react-native-pdf react-native-video (with onProgress tracking) AWS S3 pre-signed URLs (short expiry) Custom seek-detection logic in video onSeek callback
Document watermarking
Every page of every PDF opened by a trainee shows a translucent watermark overlay with their Employee ID and name. This is applied as a React Native overlay layer on top of the PDF viewer — not baked into the file, so original remains clean. Deters screenshot sharing.
Trainee sees their own watermark
Stack: React Native View overlay on PDF component Or server-side: PyMuPDF (fitz) adds watermark before pre-sign
Flashcards / quick bytes
Short micro-learning cards (text + image) accessible from any session or topic. Trainee swipes through cards like a deck. Available offline once synced. Useful for field safety refreshers while waiting at a site. Trainer can assign specific flashcard decks to a session.
Trainee uses
Stack: React Native FlatList with horizontal swipe react-native-sqlite-storage (offline card data) FastAPI /flashcards/{topic_id}
Trainer scoring during session
Field practical scoring
For physical drills (fire evacuation, equipment handling), trainer opens a scoring screen per trainee. Criteria are predefined (configurable by admin). Trainer taps scores 1–5 per criterion and adds a text comment. Scores are saved immediately to the server. If offline, saved locally and synced on reconnect.
Trainer scores
Stack: React Native rating/slider UI FastAPI /assessments/practical-score react-native-sqlite-storage (offline queue)
Phase 5 — Assessment, AI Proctoring & Shared Device
The most critical phase. Post-training test with full integrity enforcement. Includes the shared device flow for trainees without phones.
Sprints 11–13 · Weeks 21–26
Post-training assessment
Locked exam mode
When trainee starts the post-test, the app enters a locked state: status bar hidden, navigation bar hidden, back button disabled, app-switch detection active. If trainee minimizes the app or switches to another app, a warning is logged and shown. Third switch = auto-submit with integrity flag.
Trainee is locked in
Stack: react-navigation (disable back) Android: AppState API + FLAG_SECURE window iOS: UIApplication backgrounding detection FastAPI /assessments/log-integrity-event
Randomized MCQ + timer
Questions pulled randomly from the question bank for this topic. Options within each question also shuffled. Countdown timer displayed prominently — auto-submits when time runs out. Trainee cannot go back to a previous question once answered (configurable). Results calculated instantly on submit.
Trainee answers
Stack: FastAPI /assessments/fetch-questions (randomized server-side) React Native countdown timer (useEffect + setInterval) MySQL question_bank, assessment_sessions tables
AI random snapshot proctoring
During the test, the front camera fires at random intervals (every 2–5 minutes, randomized so trainee cannot predict it). Each snapshot is sent to AWS Rekognition which compares it against the HR profile photo. No match = integrity alert logged. Multiple faces in frame = alert logged. All photos stored in S3 with GPS tag and timestamp.
Trainee is monitoredTrainer reviews flags
Stack: react-native-camera (background capture) AWS Rekognition CompareFaces + DetectFaces AWS S3 (photo + GPS metadata storage) FastAPI /proctoring/snapshot
Auto-grading + instant result screen
On submit, server grades all objective questions, calculates score percentage, compares against passing threshold configured per module. Trainee sees score, pass/fail status, and which questions they got wrong with correct answers shown. If failed, retake countdown starts (if retakes allowed by policy).
Trainee sees result
Stack: FastAPI /assessments/submit + /assessments/grade MySQL assessment_results, passing_thresholds tables
Dual digital signature
After result shown, trainee draws their signature on a canvas. Signature is saved as PNG with session ID, timestamp, GPS. Then the trainer or supervisor opens a PIN prompt, authenticates, and draws their own signature. Both signatures stored in S3 and linked to the session record — audit evidence.
Trainee signs firstTrainer / Supervisor signs second
Stack: react-native-signature-canvas AWS S3 for PNG signature storage FastAPI /sessions/sign
Shared device flow (for trainees without personal phones)
Supervisor proxy login + batch mode
Supervisor logs into the app on the shared device via their own OTP. They see a "Start Batch Session" button. They select the training session and see the list of enrolled trainees who need to be tested. They verify each trainee's physical ID card before selecting their name.
Supervisor initiates
Stack: FastAPI /supervisor/batch-session MySQL: supervisor_sessions table tracking batch state
Handover — locked exam for single trainee
Supervisor taps trainee's name → app switches to that trainee's locked exam screen → supervisor hands device to trainee. Trainee completes the test. On submit, a "Return device to supervisor" screen appears and the app locks again. Supervisor enters PIN to unlock and regain access. Then selects next trainee. Cycle repeats for all 20–30.
Supervisor manages handoverTrainee completes test
Stack: React Navigation locked stack (no back, no nav bar) Android FLAG_SECURE, iOS guided access (advisory) react-native-biometrics (supervisor PIN/biometric unlock)
Post-exam photo + supervisor sign-off
After each trainee completes, supervisor is prompted to photograph the trainee (or both together). This photo is AI-matched to confirm correct identity was tested. Supervisor then provides digital signature. Only then does the session for that trainee close and the next one opens.
Supervisor photographs and signs
Stack: react-native-camera AWS Rekognition (face match) react-native-signature-canvas FastAPI /supervisor/complete-trainee
Phase 6 — Post-training, Compliance Loop & Storage
Certificate generation, feedback, offline sync, the ongoing compliance engine, and smart storage management.
Sprints 14–16 · Weeks 27–32
Post-session actions
Mandatory feedback form
After results are published, training record is not finalized until feedback is submitted. Trainee sees a feedback form: rating sliders for trainer clarity, content relevance, venue quality, plus a free-text comment. Cannot skip this — "View Certificate" button is locked until submitted.
Trainee submits (mandatory)Trainer submits trainee observations
Stack: React Native form with rating stars/sliders FastAPI /feedback/submit MySQL session_feedback table
Digital certificate auto-generation
On passing score + feedback submitted, a branded digital certificate is auto-generated with trainee name, topic, score, date, and expiry date. Displayed inside the app profile. Certificate has a unique ID that can be verified by scanning a QR on it. Company logo and branding applied from white-label settings.
Trainee receives
Stack: ReportLab or WeasyPrint (Python PDF generation) AWS S3 (certificate storage) FastAPI /certificates/generate
Offline sync — "Sync All" button
If entire session was conducted in a dead zone (no internet), all data is queued locally: attendance, scores, photos, signatures. Supervisor sees a "Sync All" banner when back on network. One tap pushes everything to the server in order. Conflict resolution: server timestamp wins if duplicate data exists.
Supervisor syncsTrainer syncs
Stack: react-native-sqlite-storage (local queue) NetInfo (@react-native-community/netinfo) for connectivity FastAPI /sync/batch-upload (idempotent endpoint)
Smart storage management
30-day inactivity tracker + auto-archive
A background service checks last-accessed timestamp for every downloaded module. At Day 25 → push notification "Module X will be removed in 5 days." At Day 28 → final warning. At Day 30 → files deleted from device, completion record remains visible. User can re-download anytime via Cloud-Fetch button.
Trainee is notified and manages
Stack: react-native-background-fetch (background job) react-native-fs (file deletion) react-native-sqlite-storage (last_accessed tracking) Firebase FCM (local scheduled notification)
Storage manager UI
In app Settings → Storage screen, trainee sees a visual bar showing total space used by training materials vs device available storage. List of downloaded modules with individual file sizes. Manual archive button per module. "Clear All Cache" button for temp files. Background cleanup runs during device idle/charging.
Trainee manages
Stack: react-native-fs (getFreeDiskStorage, getFSInfo) React Native Animated (storage bar visualization)
Compliance loop — ongoing (runs forever in background)
Expiry tracking + T-30/15/5 alerts
Every certificate has an expiry date. Server-side Celery beat job runs daily, checks all certificates nearing expiry. At T-30, T-15, T-5 days: pushes multi-channel alert (push + SMS + email) to trainee and their supervisor. Alert shows which module is expiring and a "Start Renewal" deep link into the app.
Trainee receives alertsSupervisor receives alerts
Stack: Celery beat (daily expiry scan job) Firebase FCM (push) MSG91 (SMS) SendGrid (email) Deep link into app (React Navigation linking)
Compliance status on trainee profile
Trainee home screen shows a "Compliance Status" badge — green (all certs valid), amber (expiring soon), red (expired). Tapping it opens a list of all certificates with their expiry dates and renewal status. Expired certs show a "Renew Now" button that deep-links to the relevant training enrollment.
Trainee sees own status
Stack: FastAPI /compliance/status/{user_id} MySQL certificates, validity_periods tables React Native badge + FlatList
